# Architecture rules
- Field report updates and uploads must preserve newer offline edits; manual submission waits for draft uploads before confirming persistence, so autosave cannot overwrite a submitted report.
- Field report completion uses confirmed uploads, not local submission intent; queued uploads remain retryable and shared field-work notifications refresh the UI without overwriting newer edits.
- Shared snapshot triggers compare row fields through JSON rather than direct record access, because reporting tables do not all expose the same snapshot columns.
- Manual work-day shortcuts use the shared normal-day duration and fill consistent start/end times in order forms, so database hour recalculation cannot change the chosen duration.- Time-entry locking on completed orders is enforced by a DB trigger (admins/superusers exempt) and mirrored in UI via `isTimeLocked()`, so installers cannot bypass the lock from any screen.
- The commercial track is hidden behind `COMMERCIAL_TRACK_ENABLED` in src/lib/commercial.ts; data and DB rules are kept so it can be re-enabled without migrations.
- Work order report exports (single and combined) go through `loadFieldReportData` + `exportFieldReport*` in src/lib/fieldReportExport.ts with an exclude set, so client/internal variants never diverge.
- Weekends on the planning board are non-working unless `projects.works_weekends` is set; bars and time-day requirements both read that flag.
- Sub-vendor access goes only through the `subvendor-access` backend function with a hashed one-order link token (`work_order_links`), returning whitelisted site fields; never give sub-vendors accounts or direct table access, so client pricing/contract data can't leak.
- Per diem (traktamente) amounts are computed only by the `compute_per_diem_entry` DB trigger from the yearly `per_diem_rates` table (Skatteverket, keyed by Swedish country name); src/lib/perDiem.ts mirrors it for previews, so rates change by data, not code.
- Test data is marked with `sandbox = true` on installers/projects/clients (auto-set by the `mark_test_data` trigger for TEST- tags or test accounts) and filtered out via src/lib/testData.ts in appData and report loaders, so reports never include test rows while test accounts still see their own.
